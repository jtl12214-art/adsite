# PixCompress (이미지 용량 줄이기) — v1

JPG/JPEG · PNG · WEBP 파일 **1장**을 서버 업로드 없이 브라우저 안에서 압축하는 독립형 정적 웹사이트입니다.

## 시작하기

`index.html` 파일을 Chrome, Edge 등 최신 브라우저로 열거나, VS Code의 Live Server로 실행합니다. 인터넷 연결 없이 사용할 수 있도록 `assets/js/jquery.min.js` (jQuery 3.6.1, MIT License)를 함께 포함했습니다. 압축 파일은 모두 사용자의 브라우저에서 생성되며 외부 서버에 전송하지 않습니다.

## 폴더 구조

```
index.html
assets/
  css/reset.css
  css/normalize.css
  css/commons.css
  css/style.css
  js/jquery.min.js  # 오프라인 동작을 위한 로컬 의존성
  js/main.js
  images/           # 향후 정적 이미지 자산용, 현재 비어 있음
```

## 이용 방법

1. JPG, PNG, WEBP 파일 하나를 선택하거나 드래그하여 놓습니다.
2. 100KB/200KB/500KB/1MB 또는 직접 입력(10~25,600KB)을 선택합니다.
3. JPEG/WEBP/PNG 출력 형식을 선택하고 **이미지 압축하기**를 누릅니다.
4. 전후 이미지, 실제 파일 크기, 해상도, 목표 달성 여부를 확인합니다.
5. **압축 이미지 다운로드**를 눌러 `원본이름-pixcompress.확장자`를 저장합니다.

## 압축 원칙과 한계

- **1KB=1,024바이트**, **1MB=1,024KB**로 계산하며 목표 비교는 실제 `Blob.size`를 사용합니다.
- JPEG/WEBP: 품질 0.56~0.92 구간에서 제한된 횟수의 이진 탐색을 실시하고, 필요 시 원본 종횡비를 유지하며 단계별 축소합니다.
- PNG: 품질 슬라이더로 크기를 줄일 수 없으므로 이미지 해상도 축소만으로 목표 달성을 시도합니다.
- JPEG는 투명도를 지원하지 않기 때문에 투명 영역을 흰색으로 만듭니다. PNG와 WEBP는 투명도를 보존합니다.
- 결과 MIME과 파일 헤더가 선택한 포맷과 실제로 맞는지 확인합니다. 브라우저가 WEBP 인코딩을 지원하지 않으면 오류를 표시합니다.
- 높은 화질을 유지하려는 하한 설정 때문에 **목표 용량을 달성하지 못할 수 있습니다.** 이때도 실제 결과 크기와 미달 여부를 표시합니다.
- 이미 파일 크기가 목표 이하이고 출력 형식이 원본과 같다면 재인코딩하지 않습니다.
- 이미지 파일 상한 25MB, 화소 수 상한 2,400만, 가로/세로 한 변 상한 10,000px.
- 실험적인 초대형 이미지, 메모리가 부족한 기기, 일부 브라우저에서는 Canvas 처리에 실패할 수 있습니다.
- 원본 EXIF/ICC 등 일부 메타데이터는 Canvas 재인코딩 시 제거될 수 있습니다. 이 도구는 원본 파일을 수정하지 않습니다.

## 확인용 수동 테스트

- JPG/PNG/WEBP 각각 업로드 후 출력 JPEG/WEBP/PNG로 변환하고 실제 파일 형식을 검사합니다.
- 목표 용량 프리셋 4종과 직접 입력, 비정상적인 직접 입력을 확인합니다.
- PNG에서 목표 미달 시 정확한 안내가 보이는지 확인합니다.
- 투명 PNG → JPEG의 흰색 배경, PNG/WEBP의 알파 채널 유지를 확인합니다.
- 설정/파일을 변경하면 이전 결과가 제거되고 다운로드가 비활성화되는지 확인합니다.
- 모바일(375~420px), 태블릿 및 PC에서 가로 스크롤과 UI 겹침이 없는지 확인합니다.
